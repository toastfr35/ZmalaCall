Tracked in [issue #172](https://github.com/toastfr35/ZmalaCall/issues/172).
This review covers component ownership, requirement/test/code trace consistency,
configuration admission, image input boundaries and developer documentation.
It is not a certification of every runtime path or a new physical qualification run.

## Impact review

Changed runtime contracts are `LLR-TERM-COM-004`, `LLR-TERM-COM-005` and
`LLR-AND-ENROLL-002`. Their parent outcomes remain valid: admit configuration
matching the enrolled identity before applying it. Existing server responses use
the accepted field forms. Valid enrollment, ordinary calls, installers and user
workflows are unchanged. `LLR-SRV-DIR-021/022` now reference the field validators
that already enforce the account policy; rejected edits preserve state/revision.

The longer Android UI/call and terminal audio records received paragraph changes
only. A normalized-word comparison against the base confirms their normative
wording is unchanged. Requirement IDs, hierarchy and review stamps are preserved;
no requirement has been stamped reviewed and no hardware plan has been marked passed.

Image tooling remains outside the product baseline. Installed shared host behavior
stays in `zmala_system/`, with server/terminal requirement and test links. The move
does not change installed paths, service identities, package intent or lock bytes.
Run the builder as `python3 -m zmala_images`; the old internal module path is retired.
Existing cache/output directories are retained. A new builder source hash is
expected for new build evidence; old manifests do not establish a build of this revision.

The release-guide authoring source still describes the same supported SSH
installers, APK installation and successful QR workflows. Word/PDF user guides
therefore require no content change or regeneration for this patch. Experimental
SD media remain explicitly outside those installation instructions. Android is
raised to version **0.3.93**, code **102**, for the required release-version policy.

## Remaining qualification and maintenance work

Physical Pi boot, power-loss recovery, exact card capacity/expansion, first-owner
and TLS onboarding, joint server/terminal health and automatic system updates
remain image qualification gates. No full disk image was rebuilt or card flashed
for this source move. Display/device tests and vendor background policies need
appropriate hardware; portable or JVM results cannot replace those runs.

Some established Android and terminal LLRs still contain several related clauses.
Paragraph grouping improves readability without inventing new trace coverage.
Future semantic splits should allocate new IDs with `--next-id` and move direct
assertions and references deliberately; a bulk renumbering would lose historical
identity. The current structural report does not prove complete assertion coverage
of every clause. No new baseline inconsistency was accepted to make the checks pass.
